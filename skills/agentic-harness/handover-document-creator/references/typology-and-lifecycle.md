# Relationship to Other Typologies, and Lifecycle Detail

## Relationship to other typologies

`.context/handovers/` is a distinct, standalone typology from `.context/follow-ups/`, `.context/plans/`,
and `.context/findings/` (which are created via the `create-context-file` skill and tracked in the
auto-generated `.context/index.yaml`). A handover is broader than a single follow-up item: it is the
whole session's end state, of which individual outstanding items may each already be (or become) their
own follow-up entries. Do not fold handover documents into `.context/index.yaml`'s typology; that index
is generated by the `context-index` skill for its own fixed category set (findings/plans/follow-ups/other)
and this skill does not extend it. If a handover needs to be discoverable alongside those, link it from a
`related` follow-up/plan entry instead of trying to register it in the index.

## Why a handover is a snapshot, not a living document

One dated file per handover, following the same `YYYY-MM-DD-<slug>.md` convention as
`.context/follow-ups/` and `.context/plans/`. If the same topic needs a second handover later (a session
picks up the first, makes progress, then itself hands off again), write a **new** dated file and set its
`supersedes` frontmatter field to the earlier one's path, rather than editing the original in place.

This differs deliberately from the `tool-review-assessment` skill's in-place-edit convention: a tool
assessment tracks one evolving verdict, but a handover is a record of a specific session's end state and
should not be silently rewritten by whoever picks it up. Losing the first session's own account of what
it left behind removes the audit trail a handover exists to provide.

## Status lifecycle detail

- `active`: not yet picked up, or picked up but not fully resolved.
- `done`: a session picked this up and closed out the outstanding work. Flip in the same change that
  resolves it, never delete the file, matching the `create-context-file` follow-up lifecycle
  (`status: active` until actioned, then `done`).
- `superseded`: replaced by a newer handover on the same branch/topic (the newer handover's `supersedes`
  field points back at this one).

If only some outstanding items were resolved on pickup, leave `status: active` and update
`## Outstanding` to reflect what remains, rather than marking the whole handover done prematurely.
