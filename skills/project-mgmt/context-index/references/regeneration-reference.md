# Context Index Regeneration Reference

Technical details and edge cases for the scripts in `scripts/`.

## How `regenerate-context-index.sh` Works

1. Recursively finds every `.md` file under `.context/`.
2. Parses YAML frontmatter (the text between the opening and closing `---`
   delimiters) from each file.
3. Extracts `title`, `type`, `status`, `date`, plus `tags` and `related` when
   present.
4. Skips files with missing or malformed frontmatter, printing them to
   stderr.
5. Groups the remaining entries by typology (the plural directory name) and
   sorts each group by path.
6. Writes `.context/index.yaml`.

## Typology Grouping

| `type:` (singular, in frontmatter) | Directory (plural) | Index section |
| --- | --- | --- |
| `finding` | `findings/` | `findings:` |
| `plan` | `plans/` | `plans:` |
| `guide` | `guides/` | `guides:` |
| `follow-up` | `follow-ups/` | `follow-ups:` |
| `merge-request` | `merge-requests/` | `merge-requests:` |
| `ticket` | `tickets/` | `tickets:` |
| `decision` | `decisions/` | `decisions:` |
| `note` | `notes/` | `notes:` |
| `research` | `research/` | `research:` |

A file whose `type:` doesn't match this table, or whose directory isn't one
of the nine above, still gets indexed — it lands in a catch-all `other:`
section rather than being dropped, so a one-off `--allow-new-type` folder
from `create-context-file` is still discoverable. A file whose `type:`
disagrees with the typology its *own* directory implies (e.g. `type: finding`
under `.context/plans/`) is kept in the index under its `type:` value, but
reported as a mismatch on stderr — that combination is a bug in the file, not
a legitimate new category.

## Output Format

```yaml
# Auto-generated by context-index skill. Do not edit manually.
# Last updated: 2026-08-24
# 2 entries: 1 active, 1 draft
# ── Plans (1) ──
plans:
  - path: ".context/plans/add-structured-logging.md"
    title: "Plan: Add Structured Logging"
    status: active
    date: "2026-06-30"
    tags:
      - logging
# ── Findings (1) ──
findings:
  - path: ".context/findings/2026-06-30-logging-evaluation.md"
    title: "Finding: Logging Library Evaluation"
    status: active
    date: "2026-06-30"
    related:
      - "../plans/add-structured-logging.md"
```

`tags` and `related` are only emitted when the source file's frontmatter has
at least one item; an empty `tags: []` in the source produces no `tags:` key
in the index entry.

## Exit Codes

| Script | Code | Meaning |
| --- | --- | --- |
| `regenerate-context-index.sh` | 0 | Index written (stderr may still list excluded files) |
| `regenerate-context-index.sh --check` | 0 | Index already matches what regeneration would produce |
| `regenerate-context-index.sh --check` | 1 | Index is stale — regenerate and commit the result |
| `check-context-frontmatter.sh` | 0 | Every file starts with `---` |
| `check-context-frontmatter.sh` | 1 | At least one file is missing the opening delimiter |
| `validate-context-frontmatter.sh` | 0 | Every file's frontmatter matches the full schema |
| `validate-context-frontmatter.sh` | 1 | At least one field is missing, out-of-enum, or malformed |
| `check-context-filenames.sh` | 0 | Every file in a known typology directory follows the naming convention |
| `check-context-filenames.sh` | 1 | At least one filename or date mismatch found |
| `check-plan-staleness.sh` | 0 | Always — this check is advisory, never blocking |

## Common Issues

| Issue | Cause | Fix |
| --- | --- | --- |
| A file appears under `.context/` but not in the index | Missing or malformed frontmatter | Run `check-context-frontmatter.sh`, then `validate-context-frontmatter.sh`, to identify and fix it |
| Index has duplicate-looking entries after a rename | The old and new paths both existed at some point | Regenerate — the index only ever reflects the files present at generation time |
| Index is empty after regeneration | No `.md` file under `.context/` has valid frontmatter yet | Verify files exist and start with a `---\ntitle: ...\n---` block |
| A finding/plan/etc. lands in `other:` | Its `type:` value isn't one of the nine known singular forms | Fix the typo, or confirm it's an intentional `--allow-new-type` typology |

## Wiring Into a Pre-Commit Gate

`regenerate-context-index.sh --check` and `validate-context-frontmatter.sh`
both exit non-zero on a real problem and print nothing when there is nothing
to fix, which makes them safe to wire into a pre-commit hook or CI job
without extra glue:

```bash
./scripts/validate-context-frontmatter.sh $(git diff --cached --name-only -- '.context/**/*.md')
./scripts/regenerate-context-index.sh --check
```

## Verification

```bash
# Check which files are missing frontmatter entirely
./scripts/check-context-frontmatter.sh .context/**/*.md

# Full schema validation (enums, date pattern, required tags key)
./scripts/validate-context-frontmatter.sh .context/**/*.md

# Regenerate and inspect the result
./scripts/regenerate-context-index.sh
grep '^  status:' .context/index.yaml | sort | uniq -c
```

## Best Practices

- Regenerate after every `.context/` file create, rename, or delete.
- Always resolve frontmatter warnings before treating the index as complete.
- Stage `.context/index.yaml` alongside any `.context/` file change.
- Do not hand-edit the index — it is a generated cache.
